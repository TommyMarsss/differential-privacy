# differential-privacy · Laplace 机制计数查询系统

用 Go（仅标准库）实现的**纯 ε-差分隐私计数查询**演示系统：给定数据集与一串
计数查询请求，为每个结果注入 Laplace 噪声、对隐私预算逐笔记账、拒绝超预算
查询、识别会快速耗尽预算的低效查询模式，并生成一份**数据与逻辑全部内嵌的
单一静态 HTML 报告**（原生 HTML/CSS/JavaScript，无任何框架、图形库或外部
资源，无需启动服务，浏览器直接打开）。

## 快速开始

```bash
go run ./cmd/dpdemo                 # 固定随机种子，生成 ./report.html
go run ./cmd/dpdemo -seed 42 -o r.html
go test ./...                       # 全部自动化测试
go test -race ./...
```

控制台会逐笔打印「已发布 / 已拒绝」、真实值、发布值与剩余预算；
浏览器打开 `report.html` 可查看每次查询的真实值、加噪原始值、取整截断后的
发布值、申请前后的预算快照，被拒绝的查询整行红色高亮，并附低效模式分析。

## 一、差分隐私模型与 Laplace 机制

**定义（ε-DP）**：随机机制 M 满足 ε-差分隐私，当且仅当对任意仅相差一条
记录的相邻数据集 x、x′ 与任意输出集合 S：

```
Pr[M(x) ∈ S] ≤ exp(ε) · Pr[M(x′) ∈ S]
```

ε>0 越小隐私越强；本系统只处理 **纯 ε-DP（δ=0）**。

**敏感度**：单表计数查询（一条记录至多被计数一次）的 L1 敏感度
Δ=1，因为增删一条记录最多让计数改变 1。`Query.Sensitivity` 可显式覆盖
（例如同一行被多次计数的向量查询），系统用它而不是假定恒为 1。

**Laplace 机制**：对计数 f(x) 发布

```
M(x) = f(x) + Lap(0, b),   b = Δ / ε
```

噪声通过逆变换采样生成（U 为 [−½, ½) 上的均匀变量）：

```
X = −b · sgn(U) · ln(1 − 2|U|)
```

理论性质 **E[X]=0、Var(X)=2b²**。测试以 200 000 个样本（b ∈ {0.5, 2, 5}）
在约 5 倍标准误内验证经验均值趋近 0、经验方差趋近 2b²，并用
P(|X|>t)=exp(−t/b) 与正负对称性校验分布形状——尺度参数错误（如误用
2Δ/ε、Δ/√(2ε) 或 Gaussian 尺度）会同时在方差与生存概率上暴露。

**后处理**：加噪值四舍五入并截断到非负整数作为发布值。后处理不接触原始
数据，不削弱 DP 保证，也不再额外计费。

## 二、预算记账规则

- 记账器保存 `(total, used)`，每笔**已批准**查询把其 ε **线性累加**进
  `used`，无折扣、无重置。
- **先检查后执行**：`used + ε > total`（含 1e-12 浮点容差，仅用于消化
  0.3+0.3+0.3 一类表示误差）时，查询在注入噪声之前即被拒绝：
  **不消耗预算、不抽样、不发布任何结果**，并返回明确的拒绝原因
  （当前已用、申请后将达、上限、剩余四要素）。
- ε 非正、NaN、±Inf 一律视为非法参数拒绝，且不与“预算不足”混淆。
- 预算恰好耗尽（相等）时允许最后一笔；此后任何正数 ε 都被拒绝。
- 被拒绝不影响后续查询：剩余预算仍可被更小的申请使用。

## 三、组合定理及其应用范围

**简单顺序组合（basic sequential composition）**：在同一数据集上依次
发布满足 ε₁-DP、…、εₖ-DP 的机制，其组合机制满足
`(Σ εᵢ)-DP`。本系统据此逐笔累加，这也是预算上限能约束整体隐私损失的
依据。

> 适用范围：本系统只使用**纯 ε-DP + 简单顺序组合**。
> **不**实现高级组合（advanced composition）、Rényi DP、零集中 DP、
> Gaussian 机制（(ε,δ)-DP）或跨不同数据集的并行组合（parallel
> composition）。当用户把互不相交的子群体拆成多次查询时，它们在理论上
> 本可按并行组合只计一次 ε；本系统**仍按顺序组合保守计费**，但会在低效
> 模式分析中提示如何改写查询。

### 低效查询模式识别

分析只使用查询的命中记录集合与元数据（不使用噪声，与 DP 保证无关）：

1. **duplicate（高）**：两次查询命中完全相同的记录集合——重复发布，
   直接复用上一次加噪答案即可，后一笔 ε 完全浪费。
2. **derivable（高）**：某次计数可由若干**两两不相交**的较早查询
   无重叠求和得到。求和是后处理、不耗预算；“先查总数、再逐桶拆查”时，
   总数那一问即属此类。判定被精确化为一个**精确覆盖**问题
   （Algorithm X 风格 DFS，带 10 万节点预算，宁漏报不误报），重叠集合
   不会被误判。
3. **histogram-opportunity（中）**：三个及以上两两不相交的子集计数被
   拆成独立查询。合并为一次向量（直方图）发布时，一条记录至多落入一个
   桶，向量 **L1 敏感度仍为 1**，按组内最大单笔 ε 发布即可保持每个桶
   噪声不增大，节省量 ≈ Σεᵢ − max εᵢ。

## 四、报告与安全细节

- 报告为单一 HTML 文件，样式与脚本全部内联，无 `http(s)://`、`src=`、
  `<link>`、CDN 等任何外部引用。
- 报告数据以 JSON 内联进 `<script>`。序列化后对 `<`、`>`、`&`、
  U+2028、U+2029 做 JS 转义，使查询名中的 `</script>` 等内容无法截断
  脚本（有专门测试验证）；前端渲染统一走 `textContent` 与转义函数。
- 报告中同时展示真实值仅用于**离线对照与教学**；真实对外发布的只有
  加噪结果。
